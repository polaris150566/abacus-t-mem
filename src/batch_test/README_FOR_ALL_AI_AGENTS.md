# README FOR ALL AI AGENTS

1. No matter what AI agent you are, whether Claude, Codex, OpenCode, DeepSeek, GLM, or anything else, you must read this file completely before executing any task in this directory.

2. In this directory, the only allowed shell script is `/home/chenty/abacust_mem/src/batch_test/run_tmpdb_batch_test.sh`. Never create a new `.sh` file for a task. Do not create one-off, temporary, copied, patched, or experiment-specific shell scripts. Creating a new `.sh` file and then executing it is also forbidden.

3. `run_tmpdb_batch_test.sh` is the single template for TMPDB batch testing. Its key parameters are:

- `CHECKPOINTS`: one checkpoint path per run spec. The current base setup uses checkpoint80, checkpoint90, and checkpoint100 from `abacust_mem_zero_with_0124_cluster_dict_b64_lr25`.
- `TM_RAWS`: one `tm_raw` string per checkpoint. This string is passed to `batch_seq_design_with_lig_raw_pdb.py --tm_raw` and is also used by `batch_sample.py` to build the output path. The output root is `SEQ_OUT_DIR/T_${TEMPERATURE}_R_${ITER_NUM}_esm_refined_${tm_raw}/${checkpoint_stem}` when CFG and membrane background weights are default. If `cfg_guidance_scale != 1.0`, `_w${cfg}` is appended after `tm_raw`; if `mem_bg_weight != 0.0`, `_mbg${weight}` is appended after `tm_raw`.
- `DEVICE_LISTS`: one GPU list per checkpoint. Each entry can be a single GPU such as `1`, or a comma-separated list such as `1,4,6`. `batch_sample.py` splits the target list round-robin across the GPUs in that entry. For each child process it sets `CUDA_VISIBLE_DEVICES` to the physical GPU id, while the underlying Python command still uses `--device cuda:0` inside that restricted visibility.
- `MEM_CONFIGS`: one optional membrane config path per checkpoint. Use an empty string when no mem config is required. If a single config is passed through `batch_sample.py`, it may be broadcast to all checkpoints; in this shell template, keep the array aligned with `CHECKPOINTS`.
- `CFG_SCALES`: one CFG guidance scale per checkpoint. `1.0` means no CFG tag and no extra command argument. Non-1.0 values add `--cfg_guidance_scale` and change the output directory tag.
- `BATCH_SIZE`: requested number of designs per target. The default is `10`. Internally, `batch_seq_design_with_lig_raw_pdb.py` may reduce `single_batchsize` based on protein length and run multiple epochs so that `single_batchsize * epochs >= BATCH_SIZE`.
- `TEMPERATURE`: sampling temperature. It is included in the output path as `T_${TEMPERATURE}`.
- `ITER_NUM`: number of design iterations. It is included in the output path as `R_${ITER_NUM}`. With `ITER_NUM=20`, the last iteration index is normally `19`.
- `FEATURE_NUM_WORKERS`: worker count for feature generation if `run_feature_step` is enabled.
- `run_prepare_step`, `run_feature_step`, `run_sample_step`, and `run_gather_step`: the `main` function controls which stages run. At present only `run_sample_step` is enabled. Uncomment only the intended stage; do not create a new shell script.
- PDB generation: `run_tmpdb_batch_test.sh` calls `batch_sample.py`, and `batch_sample.py` currently always includes `--write_allatom_model` in the command it launches. Therefore runs through this template currently request all-atom PDB output. If a task requires changing whether PDBs are generated, inspect and modify the existing Python/template path deliberately; do not create another `.sh` file.

4. After a test run finishes, always check whether the current run output already contains merged FASTA files. The merged FASTA path is per target under the checkpoint output directory, with the format `{target}/{target_lowercase}_merged.fasta` as produced by `batch_gather_result.py` (for example, a target directory should contain one `*_merged.fasta`). If the merged FASTA files already exist, stop; do not run extra gathering. If they do not exist, run the existing `batch_gather_result.py` program to generate them, then actively verify the result. For a run configured to generate `BATCH_SIZE=10` design sequences, the number of design records in each merged FASTA, excluding the first native/template record, must be either `10` or `12`. Equivalently, the total number of FASTA headers including the first native/template record must be either `11` or `13`. If this count is not satisfied, do not silently continue; report the mismatch and inspect the failed target/output directory.

5. Output naming conventions and recovery calculation rules:

- Per-epoch raw FASTA files are named `{target}_{epoch_index}_design.fa`. Because many target names already end with `_`, real files often look like `9ps8_297_homo__0_design.fa`. The number before `_design.fa` is the outer epoch index used to split `BATCH_SIZE` into smaller GPU batches.
- Inside each raw FASTA, the native/template record is written first. Design records are named `{target}_design_{b_idx}_{iter_idx}`. Here `{b_idx}` is the sample index inside the current mini-batch, and `{iter_idx}` is the zero-based design iteration index. For `ITER_NUM=20`, raw final-iteration records have `{iter_idx}=19`.
- `batch_gather_result.py` creates one merged FASTA per target named `{target_lowercase}_merged.fasta`. It reads the raw FASTA files and keeps only the final-iteration design records from each raw file by taking the last records. Earlier iteration records are not used in the merged FASTA.
- Design records inside a merged FASTA are renamed `{target_lowercase}_design_{i}_{iter_number}`. Here `{i}` is the global design index after gathering, and `{iter_number}` is the configured iteration count passed to `batch_gather_result.py` such as `20`. This merged label uses `20` for an `ITER_NUM=20` run even though the raw zero-based final iteration index is `19`.
- Current all-atom PDB naming in `batch_seq_design_with_lig_raw_pdb.py`: native/template PDBs are named `{target}_{epoch_index}.pdb`; design PDBs, when written, are named `{target}_design_{global_b_idx}_{last_iter}.pdb`. `{global_b_idx} = epoch_index * n_batch + b_idx`; `{last_iter}` is zero-based, so it is normally `19` when `ITER_NUM=20`.
- Recovery statistics must be computed only from the final-iteration sequences in the merged FASTA. Ignore all earlier iteration sequences in the per-epoch raw FASTA files. `batch_gather_result.py` is responsible for selecting the final-iteration records before `recovery_stats.csv` is computed.

6. When computing metrics, always report both the arithmetic mean and the weighted mean. The weighted mean must use the inverse of the test protein cluster size as the weight. The cluster definition file is `/home/chenty/public_data/tmpdb_after_202505/data_storage/cluster_dict.json`. For each test protein, find its cluster in that JSON file, use `1 / cluster_size` as that protein's weight, and compute the weighted metric from those per-protein weights. Do not report only the arithmetic mean when cluster-aware weighting is required.
